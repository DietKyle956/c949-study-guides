Lists versus tuples: mutability decides

A list is written with square brackets. A tuple is written with parentheses. The syntax is only the label; the defining property is mutability - whether the container can change after it is created.

FeatureListTuple
Mutable?YesNo
Can add, remove, or replace elements?YesNo
Typical syntax[1, 2, 3](1, 2, 3)

The study guide’s example shows the property in code:

items = [1, 2, 3]
items[0] = 9          # Valid

coordinates = (1, 2, 3)
# coordinates[0] = 9  # Error

Same index, same assignment, opposite outcomes. The list accepts the replacement because it is mutable; the tuple rejects it because it is immutable. Any exam question that contrasts the two is asking this one property.

The contrast, verbatim

Lists are mutable; tuples are immutable. A list can add, remove, or replace elements; a tuple cannot.

Slicing: start included, end excluded

The operation that creates a new list containing some elements from another list is a slice, written with a start and an end separated by a colon:

my_list[start:end]

The two rules that decide every slice:

  • The starting index is included.
  • The ending index is excluded.

Work the exam’s example with the indices written out:

my_list = [10, 20, 30, 40]
index        0   1   2   3

portion = my_list[1:3]  # [20, 30]

Start at index 1, which is 20. Stop before index 3, which holds 40, so 40 never enters the slice. The result is the two elements [20, 30] - a fresh list, not a window into the original.

The exam’s sentences, verbatim

my_list[start:end] creates a new list containing some elements from another list. The starting index is included. The ending index is excluded.

Related one-liners the same study-guide section lists: my_list[index] returns one element, not a list, and my_list.pop() removes and returns an element.
