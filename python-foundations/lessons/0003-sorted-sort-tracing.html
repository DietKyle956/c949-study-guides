sorted() versus .sort(): same outcome, different return

Both calls put the elements in order. The difference the exam tests is what you get back and what happens to the original:

The exam’s sentences, verbatim

sorted(my_list) returns a new list containing the elements in sorted order. It leaves the original list unchanged.

my_list.sort() sorts the existing list in place and does not return the sorted list.

Side by side, with the same starting list:

my_list = [3, 1, 2]

new_list = sorted(my_list)   # new_list is [1, 2, 3]
                             # my_list is still [3, 1, 2]

result = my_list.sort()      # my_list becomes [1, 2, 3]
                             # result is None - nothing came back

The trap is the second call: it does the sorting and hands back nothing, so my_list.sort() in an expression is worth None. If the exam shows an assignment on the left of a sort call, the answer is either a new sorted list (sorted()) or nothing (.sort()) - the returned value is never the original list.

Tracing the loop with break

Here is the study guide’s sample loop, verbatim:

total = 0
count = 0
for i in range(1, 11):
    if i % 5 == 0:
        break
    total += i * 2
    count += 1
average = total / count
print("Average:", average)

range(1, 11) offers the values 1 through 10, but the break cuts the loop short. The condition i % 5 == 0 fires at the first multiple of 5, and break leaves the loop immediately - before the total += i * 2 line runs for that value. Walk it:

The loop processes 1, 2, 3, 4 and stops before processing 5. Then the two lines after the loop run once:

total = 2 + 4 + 6 + 8 = 20
count = 4
average = 20 / 4 = 5.0

print("Average:", average) prints its arguments separated by a space, and 20 / 4 is true division, so the value keeps its decimal point. The output is exactly:

Average: 5.0

That string is the exam’s answer. Watch the two tempting wrong traces: letting 5 contribute gives 30 over 5, which is 6.0, and letting the loop run all the way to 10 gives 110 over 10, which is 11.0 - neither is the exam’s output.

Overloaded methods: same name, different parameters

A method is overloaded when several definitions share one name and differ in their parameter list. The exam asks for that definition directly:

The definition, verbatim

Overloaded methods have the same name, different parameter lists.

Same name plus a different list of parameters is the whole rule. A different name is simply a different method; the same name with the same parameter list is a redefinition, not an overload.
