Doubly linked lists: positional insertion

The exam’s remaining linked-list rows are about the doubly linked list: what a positional list is made of, and the four links that change when a new node slides between two neighbors. This lesson drills the four-link insertion until you can write it from memory.

Why this lesson

Lesson 1 covered singly linked lists - one direction, one reference per node. A doubly linked list adds a second reference per node, and that second reference is what the exam’s positional-list question is built on. The matching table says it in four words: update doubly linked neighbor pointers.

The doubly linked node

Each node of a doubly linked list stores a value and two references: next to the following node and prev to the preceding one. You can walk the chain in either direction.

head -> [ | * | A | * | ] <-> [ | * | B | * | ] -> None

The exam’s phrasing, verbatim

Each node stores links to its previous and next neighbors and needs only pointer updates. “Pointer updates” means changing references - no shifting, ever.

Inserting between A and B

The exam’s insertion: a new node goes between nodes A and B. Four links change - two on the new node, one on A, one on B:

A.next     -> new
new.prev   -> A
new.next   -> B
B.prev     -> new
Before:  A <-> B
After:   A <-> new <-> B

How to read the four links

The new node takes A and B as its neighbors (new.prev -> A, new.next -> B), then the neighbors point back at it (A.next -> new, B.prev -> new). Only references change - A and B stay exactly where they are.

Contrast with an array again: inserting in the middle of an array shifts every later element right. Inserting in the middle of a doubly linked list changes four references and moves nothing. That contrast is the whole exam point.
