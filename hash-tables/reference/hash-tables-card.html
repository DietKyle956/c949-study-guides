The key-value idea

A hash table maps keys to values. The exam’s code:

hash_table = {}
hash_table["apple"] = 5
hash_table["banana"] = 3
hash_table["cherry"] = 8

Store and retrieve

hash_table["apple"] = 5 stores 5 under the key “apple”. hash_table["apple"] retrieves the 5. The same key that stored the value is the key that fetches it.

Contrast: a list is reached by numeric index; a hash table is reached by key.

The complexity row

Average-case insertion: O(1)

This average-case behavior assumes an effective hash function and a reasonably controlled load factor. Collisions can cause slower behavior in the worst case. The exam’s sentence, verbatim.

The pieces, in one line each:

  • Hash function - turns a key into a bucket position; effective means keys spread evenly.
  • Collision - two keys land in the same bucket; resolving them costs extra, which is the worst-case slowdown.
  • Load factor - items divided by buckets; controlled means the table grows before buckets fill up.

The exam tip

From the study guide’s strategy list: identify the defining property. “Maps keys to values” - hash table. “Average case” - O(1). “Worst case, collisions” - slower. Three phrases, three instant answers.

The O(1) rule itself comes from the Big O cheat card: any constant-time operation is O(1).
