The ADT idea

An ADT specifies what operations a data structure supports, without requiring you to know how they are implemented. The operations are the contract: a stack offers push, pop, top; a queue offers enqueue, dequeue, front - no matter whether the stack is built with an array or a linked list.

  • Focus on higher-level operations and algorithms - the exam’s benefit answer, verbatim.
  • Avoid dependence on internal implementation details.
  • Swap an implementation without changing client code that uses the ADT interface.

Records

A record stores related subitems, called fields, each with an associated name.

Student record:
  - name
  - student_id
  - program
  • Record = items by name. Array = items by position (0, 1, 2, ...). The access style is the defining property.
  • The exam’s wording to spot: “stores subitems with a name associated with each subitem”.

Arrays vs linked structures

Arrays usually offer direct index access, but inserting or removing in the middle can require shifting items. Linked structures store nodes connected by references; once the target location is known, insertion or removal updates references rather than shifting every later element.
