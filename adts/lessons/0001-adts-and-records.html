ADTs and linear structures · Lesson 1

The ADT idea: what, not how

The exam will describe a concept in one line and ask you to name it. This lesson maps the two descriptions it uses most - “what, not how” and “named subitems” - to their answers, then drills the recognition until it is instant.

Why this lesson

Two rows of the practice exam’s quick-answer table are pure identification: “Named subitems data structure” and “ADT benefit”. Neither needs calculation or tracing - they need you to spot a defining property and fire its answer. That is the same move as the Big O course’s exam-day procedure: identify the defining property first, then answer. This lesson gives you the property-to-answer map for ADTs and records.

The ADT idea

The exam’s definition, almost word for word: an ADT specifies what operations a data structure supports, without requiring users to know how those operations are implemented.

The contract: operations, not internals

Think of the operations as a menu. A stack’s menu lists push, pop, and top; a queue’s lists enqueue, dequeue, and front. What the kitchen does behind the menu is the implementation - and the customer (client code) never needs to see it.

The exam’s own example: the same stack might be implemented with an array or with a linked list, and client code still uses the same operations. The operations are the ADT; the array or the linked list is a choice made underneath it.

The exam’s benefit question

When the exam asks why ADTs matter, the answer it wants is verbatim:

Benefit of using ADTs

Focus on higher-level operations and algorithms.

The other two benefits the exam lists: avoid dependence on internal implementation details, and swap an implementation when necessary without changing client code that uses the ADT interface.

All three are one idea: the what is stable, the how can change freely. Memorize the first sentence - it is the exam’s answer row.

Records: items by name

The exam’s definition: a record stores related subitems, called fields, each with an associated name.

Student record:
  - name
  - student_id
  - program

Record = by name, array = by position

An array’s items are reached by position - index 0, 1, 2, and so on. A record’s items are reached by name - name, student_id, program. The access style is the defining property, and it is the whole question.

The exam wording to spot for a record: “stores subitems with a name associated with each subitem”. Nothing else in the phrase matters - that pattern alone is the answer.
