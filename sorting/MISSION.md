# Mission: Sorting and Selection

## Why
Pass the C949 assessment questions on sorting and selection. These are the exam's sorting rows: which sort needs the value range, the O(N + K) complexity with its two letters, and the partition idea quickselect borrows from quicksort. The user wants each exam phrase mapped to its answer so these become free points.

## Success looks like
- Given "requires knowing the range of input values", the user answers counting sort immediately.
- The user states counting sort's typical complexity as O(N + K), naming N as the number of elements and K as the range of possible values.
- The user states when counting sort is most practical: K is not dramatically larger than N.
- The user explains quickselect in the exam's words: partition the list and focus on the relevant section.
- The user states the one difference: quickselect does not recursively sort both partitions.
- Every sorting question in the practice exam is answered without notes.

## Constraints
- Simplest possible methods - exam-speed recognition, no implementation projects.
- Learning happens in short sessions; lessons must be completable in one sitting.
- Lessons must work offline and print cleanly for revision.
- Workspace lives at ~/school/c949/study_guides/sorting and is published on GitHub Pages as part of the c949-study-guides site.
- Reuses the shared stylesheet and quiz widget from the Big O workspace - same look, same interaction.

## Out of scope (for now)
- Implementing counting sort, quicksort, or quickselect in Python.
- Merge sort, heap sort, and other comparison sorts the exam does not ask about.
- Huffman coding (topic 8) and the final interleaved review (topic 9).
