Counting sort

Counting sort requires knowing the range of input values so it can create an array of counts - one slot per possible value. It never compares elements.

input:        [2, 0, 2, 1]
counts:       [1, 1, 2]
output:       [0, 1, 2, 2]

The complexity and the condition

Typical complexity: O(N + K) - N is the number of elements, K is the range of possible values. Two sequential passes, so the loops add.

Most practical when K is not dramatically larger than N. A huge range means a huge counts array for a small input.

The partition idea

Quicksort: pick a pivot, then partition elements below and above it.

Quickselect, the exam’s sentence

Quickselect finds a target rank - the kth smallest or kth largest element - without sorting the entire list. It uses partitioning to partition the list and focus on the relevant section: choose a pivot, partition, determine which partition could contain the desired rank, and continue only there.

Unlike quicksort, quickselect does not recursively sort both partitions.

The exam tip

From the study guide’s strategy list: identify the defining property. “Needs the range of input values” - counting sort. “Partition and pursue one section” - quickselect. “O(N + K)” - counting sort’s complexity. Three phrases, three instant answers.

The add rule behind O(N + K) comes from the Big O cheat card: sequential loops add.
