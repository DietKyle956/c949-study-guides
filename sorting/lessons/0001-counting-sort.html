Counting sort: the value-range sort

The exam’s sorting block opens with one identification question: which sort requires knowing the range of input values? This lesson pins the recognition, the O(N + K) complexity with its two letters, and the practicality condition, then drills them until they are instant.

The defining property: the value range

Counting sort is the only sort in the exam that asks for the range of input values. It needs the range so it can create an array of counts: one slot for every possible value, from the smallest to the largest. The exam’s identification phrase is that whole sentence.

The defining property, verbatim

Counting sort requires knowing or determining the range of input values so it can create an array of counts. Any question asking which sort needs the value range is answered counting sort.

Notice what is missing: no comparisons. Counting sort never asks which element is bigger. It counts. Lesson 2’s quicksort is the opposite - it partitions by comparing everything to a pivot. The exam separates the two by this contrast.

How it works: count, then write out

Range first: the input holds values from 0 to 2, so the counts array has three slots. Pass once over the input, counting each value:

input:        [2, 0, 2, 1]
range 0..2 -> counts array of 3 slots
counts:       [1, 1, 2]   one 0, one 1, two 2s

Then write the output from the counts: 0 once, 1 once, 2 twice:

output:       [0, 1, 2, 2]

Two passes, no comparisons. The counts array is the whole idea - the exam’s question about it is just checking you know it exists.

The complexity: O(N + K)

The exam’s complexity row names two letters. N is the number of elements in the input. K is the range of possible values - how many slots the counts array needs. The two passes become two loops, one after the other:

pass 1: count every input value     -> N steps
pass 2: write output from counts    -> K steps
total:  N + K                        -> O(N + K)

Loops in sequence add - the Big O course’s add rule. No nesting, no log, no square. The exam asks the complexity, the N, and the K; answer all three with the same sentence.

The exam’s complexity row, verbatim

Counting sort’s typical complexity is O(N + K), where N is the number of elements and K is the range of possible values.

When it is practical: the K-versus-N check

The counts array has one slot per possible value. If K explodes - say ten elements whose values run from 0 to a billion - the array is a billion slots for ten items. The exam’s practicality row captures exactly this:

The exam’s condition, verbatim

Counting sort is most practical when K is not dramatically larger than N. Small range, small counts array, quick two passes. Huge range, huge counts array, wasted slots.
