The two sentences

What it is, verbatim

Huffman coding is a lossless compression technique that uses variable-length binary codes. Lossless - the original comes back exactly. Variable-length - each character’s code is a run of 0s and 1s, and the lengths differ.

What it does, verbatim

Huffman coding assigns shorter codes to more frequent characters to reduce file size. The effect is a lower average number of bits per character. Frequent symbols use fewer bits; rare symbols use more bits.

Frequent character:  0       1 bit
Less frequent:      101      3 bits
Rare character:     11101    5 bits

The frequent character’s code is paid once per occurrence, so shortening it saves the most bits; the rare character’s long code is paid only often enough to keep it recoverable. Shorter codes for the frequent characters pull the average down, and a lower average is a smaller file.

The exam tip

From the study guide’s strategy list: identify the defining property in the question. “Lossless, and the codes have different lengths” - Huffman coding. “Shorter codes for frequent characters” - Huffman compression, the Quick Answer Review row. “A lower average number of bits per character” - the reason the file shrinks.

Then rule out choices that describe a different technique. Counting sort and quickselect belong to the sorting topic; fixed-length codes and lossy compression are the two contrasts this topic is built on.
