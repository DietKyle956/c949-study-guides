Huffman coding: shorter codes for frequent characters

Topic 8 is one exam sentence: Huffman coding is a lossless compression technique that uses variable-length binary codes, with the shortest codes handed to the most frequent characters. This lesson pins it, then drills the recognition.

What Huffman coding is: lossless, variable-length

Two words do all the work. Lossless means the original comes back exactly - every character, in order, with nothing missing, unlike lossy compression, which throws detail away for good. Variable-length binary codes means each character’s code is a run of 0s and 1s, and the runs differ in length.

The definition, verbatim

Huffman coding is a lossless compression technique that uses variable-length binary codes. A question asking what kind of compression Huffman coding is, or what kind of codes it uses, is answered from this one sentence.

Fixed-length codes are the contrast: every character costs the same number of bits, however often it appears.

The core idea: frequent gets short, rare gets long

Give the characters that appear most often the shortest codes, and the ones that barely appear the longest. The frequent character’s code is paid once per occurrence, so shortening it saves the most. The exam gives the shape of it with three characters:

Frequent character:  0       1 bit
Less frequent:      101      3 bits
Rare character:     11101    5 bits

The exam’s explanation, verbatim

Huffman coding assigns shorter codes to more frequent characters to reduce file size. The effect is a lower average number of bits per character.

The arithmetic: average bits per character

Compression happens on average, not per character. A 100-character text with five distinct characters costs 300 bits at a fixed 3 bits each; Huffman coding orders the code lengths by the counts instead:

character   count   code    bits contributed
e              60   0       60 x 1 = 60
a              25   10      25 x 2 = 50
t               9   110      9 x 3 = 27
h               4   1110     4 x 4 = 16
r               2   1111     2 x 4 =  8
total: 161 bits / 100 characters = 1.61 bits per character

Same text, same five characters, recovered exactly - but the average has fallen from 3 bits per character to 1.61. That drop is the point: short codes for the frequent characters lower the average bits per character, so the file gets smaller.
