The procedure

  1. Count the passes of every loop.
  2. Multiply nested loops (n × n = n²).
  3. Add sequential blocks (n + n = 2n).
  4. Halving loop, or doubling counter = log n.
  5. Simplify: drop constants (2n → n), keep the dominant term (n² + n → n²).

Recursion: the four shapes

Time = (work per level) × (number of levels). Shrink by a constant amount: n levels. Shrink by half: log n levels.

  • Recursion space = deepest stack = number of levels. fib(n) is O(n) space even though its time is O(2ⁿ).
  • Trap: calls doubling per level is not automatically exponential. Two halves with O(1) combine = O(n).

Recurrence levels: the one-rule version

A recurrence relation defines a function via a smaller instance of itself (its own name appears on the right side). Read T(N) = work + T(smaller) as: do the work, then call on the smaller input. Write the first three sizes; equal gaps mean subtract, equal ratios mean divide.

  • Subtract a constant k: sizes N, N − k, N − 2k, ... so levels = N / k (more exactly ceil(N / k)).
  • Divide by a factor b: sizes N, N / b, N / b², ... so levels = logb N, which is O(log N) for any b.
  • Time = work per level × levels. Space = levels (the stack).

Space: the two questions

Auxiliary space = extra memory beyond the input. Ask: does it build a container that grows with N? Is there recursion? Neither: O(1).

  • Fixed variables - counters, totals, indices: O(1). Any fixed number of them is still O(1).
  • Growing container - result list, copy, dictionary, slice: O(N). One container per element: O(N²).
  • Recursion - deepest pending stack = number of levels. Shrink by 1: O(N). Halve: O(log N). Branch: O(N) (one path on the stack at a time).
  • Input does not count - auxiliary means extra, and only memory alive at one moment counts.
  • Time and space disagree - fib is O(2ⁿ) time but O(N) space; a sum loop is O(N) time but O(1) space. Answer separately.

Traps that show up on every exam

  • Inner loop starts at i - n + (n−1) + ... + 1 = n(n+1)/2 = still O(n²).
  • Two loops of different sizes - if the input has two sizes n and m, they stay: O(n + m), or O(n × m) when nested.
  • Halving by any amount - i = i * 3, or n = n / 10, is still O(log n); the base is a constant.
  • Constants hide in n - a loop that runs n/2 times is still O(n).
  • Square-root loops - while i × i < n stops at i = √n, so it is O(√n).
  • Sequential vs nested - a loop after a loop adds; a loop inside a loop multiplies. Check the indentation.
