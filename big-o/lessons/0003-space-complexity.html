Big O for Exams · Lesson 3

Space: count the extra memory

Time is only half the question. The exam also asks how much extra memory a snippet needs - and the answer is simpler than the time answer: two questions, not three.

Why this lesson

One of the exam items is: a function named get_odd_numbers() has worst-case auxiliary space O(N). "Auxiliary space" is the phrase exam writers use for extra memory the code creates beyond the input. This lesson turns that phrase into two mechanical questions, then drills them until stating space complexity takes seconds. You will reuse the recursion-level counting from Lesson 2 for half of it.

The two questions

To state the space complexity of any snippet, ask in order:

Question 1 - Does it create a container that grows with N?

A new list, copy, dictionary, or set that fills up as the input grows costs O(N) extra memory - and N² if it builds one container per element. A fixed number of plain variables costs O(1), no matter how many there are.

Question 2 - Is there recursion?

Every unfinished call holds a stack frame, so recursion costs the deepest chain of pending calls - the number of levels from Lesson 2, not the total number of calls. Shrink by 1: O(N). Halve: O(log N). Branch: still O(N), because the stack only ever holds one path down the tree.

Neither question fires - no growing container, no recursion - and the answer is O(1) auxiliary space.

The three rules

Rule 1 - Fixed variables: O(1)

def sum_numbers(numbers):
    total = 0
    for n in numbers:
        total += n
    return total

total, n, and the loop machinery are a fixed handful of variables that do not grow with the input: O(1) auxiliary space. Ten variables would still be O(1) - constants drop here too.

Rule 2 - A container that grows with N: O(N)

def get_odd_numbers(numbers):
    odds = []
    for n in numbers:
        if n % 2 != 0:
            odds.append(n)
    return odds

odds grows with the input. Worst case, every element is odd, and the new list holds all N of them: O(N) auxiliary space. The container itself is what you count - its size is set by N, not by the loop variable.

Rule 3 - Recursion: O(depth)

def fact(n):
    if n <= 1: return 1
    return n * fact(n - 1)

n pending frames sit on the stack at once (fact(n), fact(n-1), ..., fact(1)): O(N) space. A recursive binary search halves each time, so only log n frames stack up: O(log N). A branching recursion like fib still costs O(N) - the stack holds one path at a time, however many paths exist in total.

Worked examples

Counting is not collecting

def count_odds(numbers):
    count = 0
    for n in numbers:
        if n % 2 != 0:
            count += 1
    return count

Same loop as get_odd_numbers, but it stores a counter instead of a list. One fixed variable: O(1). The difference between the two functions is the whole lesson: a growing container is O(N), a counter is O(1).

Fibonacci: time and space disagree

def fib(n):
    if n <= 1: return n
    return fib(n - 1) + fib(n - 2)

Time explodes to O(2ⁿ) because the number of calls doubles per level. Space is only the deepest pending chain: the stack holds fib(n), fib(n-1), ..., fib(1), one path - O(N). Always answer the two questions independently.

A container per element: O(N²)

def make_grid(n):
    grid = []
    for i in range(n):
        grid.append([0] * n)
    return grid

The outer list holds n rows, and each row is itself a list of n items: n × n = O(N²). Same shape as nested loops for time - multiply.

The traps

Trap 1 - The input does not count

"Auxiliary" space means extra memory beyond the input itself. Total space = input + extra, but when the question says auxiliary, count only what the function creates. get_odd_numbers receives a list of size N and builds a second list of up to size N: its auxiliary space is O(N), and its total is O(N) too - but only because the extra list happens to match the input. The distinction is the question's.

Trap 2 - Only memory alive at once counts

Space is a snapshot at the worst moment, not a sum over the run. A loop that allocates one small object per iteration and drops it before the next uses O(1) extra space. Two separate N-sized lists used one after the other are O(N) at the worst moment, not O(2N) - and constants drop anyway. Recursion obeys the same rule: the stack holds the deepest chain, not every call that ever existed.

Trap 3 - Built-ins that hand you a new container

sorted(numbers) returns a new list, so it spends O(N) auxiliary space. numbers.sort() sorts in place and, at the level this exam tests, counts as O(1) extra. Slicing (numbers[:]) also builds a new list: O(N). Whenever a built-in returns a container you did not have, that container is auxiliary space.

What is the space complexity of this binary search?

def search(a, lo, hi, target):
    if lo > hi: return -1
    mid = (lo + hi) // 2
    if a[mid] == target: return mid
    if a[mid] < target:
        return search(a, mid+1, hi, target)
    return search(a, lo, mid-1, target)
