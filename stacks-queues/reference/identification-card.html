The stack

A stack follows LIFO: last in, first out. One open end, the top; everything enters and leaves through it.

  • push(x) - add x on top of the stack.
  • pop() - remove and return the top item.
  • top() - read the top item without removing it.

The last item pushed is the first item popped. Think of a stack of cafeteria trays.

The queue

A queue follows FIFO: first in, first out. Two ends, two jobs: items enter at the back, leave at the front.

  • enqueue(x) - add x at the back.
  • dequeue() - remove and return the front item.
  • front() - read the front item without removing it.

The back computation

Given [72, 15, 2, 14], front_index = 0, length = 4: the front is the element at front_index (72), and the back is the last active element - index front_index + length - 1 = 3 (14). The front and the back are opposite ends.

The deque

A deque is a double-ended queue: insertion and removal at both ends. Four operations, one per end per job:

  • add_first(x), add_last(x) - add at the front or the back.
  • remove_first(), remove_last() - remove from the front or the back.

Ends-rules side by side: a stack has one end (the top, in and out); a queue has two ends with one job each; a deque has two ends with both jobs at both ends.

The priority queue

A priority queue removes items according to priority, not merely arrival order. The highest-priority item leaves first.

  • pq.enqueue(item, priority) - add an item with its priority.
  • pq.dequeue() - remove and return the highest-priority item.
  • pq.peek() - observe the highest-priority item without removing it.
  • pq.is_empty() - check whether the queue has items.

The contrast to spot: a plain queue removes in arrival order (FIFO); a priority queue removes in priority order.

Dynamic expansion

An array-backed unbounded stack expands dynamically so it keeps accepting pushed elements after its initial capacity fills.

Best reason, verbatim

To support continuous addition of elements without a predefined limit. Growing only as necessary can improve practical memory use; capacity doubling avoids resizing on every push.
