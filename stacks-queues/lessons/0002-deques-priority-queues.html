The deque: both ends, both jobs

A deque is a double-ended queue. The exam’s definition, nearly word for word: a data structure that allows insertion and removal of elements from both ends.

OperationWhat it does
add_first(x)add x at the front end
add_last(x)add x at the back end
remove_first()remove and return the front item
remove_last()remove and return the back item

The defining property: both ends, both jobs

Compare the three ends-rules side by side. A stack has one end and one job (the top, in and out). A queue has two ends with one job each (in at the back, out at the front). A deque has two ends with both jobs at both ends - add or remove at either end. The phrase to spot is “insertion and removal from both ends”: that phrase alone is the answer.

The priority queue: priority, not arrival order

A priority queue removes items according to priority, not merely arrival order. The highest-priority item leaves first, no matter when it arrived.

OperationWhat it does
pq.enqueue(item, priority)add an item with its priority
pq.dequeue()remove and return the highest-priority item
pq.peek()observe the highest-priority item without removing it
pq.is_empty()check whether the queue has items

The defining property: order of removal

A plain queue removes in arrival order - first in, first out. A priority queue ignores arrival order and removes the highest-priority item first. The exam’s phrase to spot: “removes items according to priority, not merely arrival order”. And when the exam asks which call removes the highest-priority item, the answer is the call itself: pq.dequeue().

The pq. prefix is just a variable name, the way my_list.sort() names the list. The exam writes the priority queue as pq - read it as “this priority queue’s dequeue”.

Dynamic expansion: why unbounded stacks grow

An array-backed stack starts with an initial capacity. Once that capacity fills, an unbounded stack expands dynamically so it keeps accepting pushed elements.

The exam’s answer, verbatim

The best reason for dynamic expansion: to support continuous addition of elements without a predefined limit.

A predefined limit would cap the stack - expansion removes the cap. The exam adds two supporting facts: growing only as necessary can improve practical memory use, and capacity doubling avoids resizing on every push.

When the exam asks “why expand”, the answer is never about sorting or ordering - it is about the cap. Spot the words “continuous addition” and “without a predefined limit” and the sentence is already written for you.
