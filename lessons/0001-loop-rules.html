Big O for Exams · Lesson 1

The Loop Rules

Almost every loop-based Big O question on an exam collapses into three rules. Learn the rules once, and “read this code, state its complexity” becomes mechanical arithmetic.

Why this lesson

On most exams, loops are the bulk of the complexity questions - single loops, nested loops, and the halving loop that everyone loses points on. This lesson turns all of them into a three-rule procedure, plus the two simplifications you apply at the end.

The two simplifications you already know

Big O only cares about how the work grows as n grows. So before anything else, remember the finish line:

Always end with these

Drop constants. O(2n) becomes O(n). O(3) becomes O(1).

Keep only the dominant term. O(n² + n) becomes O(n²).

Everything below produces an expression like 2n + 3 or n² + n. You finish by applying these two moves. That is the whole game.

The three rules

Rule 1 - Multiply: nested loops

A loop inside a loop multiplies. Count the passes of the outer loop, multiply by the passes of the inner loop.

for i in range(n):        # n passes
    for j in range(n):    # n passes each
        work(i, j)        # O(1)

n × n = O(n²). Three levels of nesting give O(n³), and so on. A loop inside a loop is multiplication - that is the whole rule.

Rule 2 - Add: sequential blocks

Code that runs one block after another adds. Then the simplifications clean it up.

for x in items:           # O(n)
    sum1 += x
for x in items:           # O(n)
    sum2 += x

O(n) + O(n) = O(2n) = O(n). If the blocks are different sizes, the biggest wins: O(n) + O(n²) = O(n²).

Rule 3 - Halve: logarithmic loops

A loop whose counter doubles each pass, or whose input halves each pass, runs log n times.

i = 1
while i < n:
    work(i)        # O(1)
    i = i * 2      # i: 1, 2, 4, 8, ...
while n > 1:
    work(n)        # O(1)
    n = n // 2     # n: 16, 8, 4, 2, 1

Both loops finish in about log₂ n passes, so both are O(log n). The base of the log never matters, because log₂ n and log₁₀ n differ only by a constant factor - and constants get dropped anyway.

Worked examples

Run the procedure top to bottom: count each loop, multiply the nested ones, add the sequential ones, then simplify.

One loop

total = 0
for x in items:      # items has n elements
    total += x

Apply: n passes × O(1) each = O(n).

Two loops, one after the other

for x in items:       # O(n)
    print(x)
for x in items:       # O(n)
    print(x)

Apply: sequential, so add: O(n) + O(n) = O(2n). Drop the constant: O(n).

Nested loops

for x in items:            # n passes
    for y in items:        # n passes each
        compare(x, y)

Apply: nested, so multiply: n × n = O(n²).

Doubling counter

i = 1
while i < n:
    print(i)
    i *= 2

Apply: the counter doubles each pass (1, 2, 4, 8, ...), so the loop runs log n times: O(log n).

Nested loop with a halving inner loop

for i in range(n):        # n passes
    j = 1
    while j < n:          # log n passes
        work(i, j)
        j *= 2

Apply: nested, so multiply: n × log n = O(n log n). This shape is how efficient sorts like merge sort behave, and exams love it.

The classic trap: inner loop starts at i

for i in range(n):
    for j in range(i, n):   # runs n - i times
        work(i, j)

Apply: it looks like less than n². Total passes = n + (n−1) + (n−2) + ... + 1 = n(n+1)/2, and n(n+1)/2 is still n² shaped. Drop the constant: O(n²). A triangular count is not a smaller Big O.
